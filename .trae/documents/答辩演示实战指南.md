# 乡村守护者 — 答辩演示实战指南

> 本文档是「答辩问答文档」的配套指南，教你**如何讲、如何演示、如何应对提问**

---

## 一、开场自我介绍（1 分钟定基调）

答辩刚开始时，评委对你的项目毫无了解。不要上来就讲技术细节，先用一段话让评委快速建立认知。

**【推荐开场白模板】**

> 各位老师好，我做的这个项目叫"乡村守护者"——一个面向农村空巢老人的智慧养老管理平台。
>
> 简单说就是三句话：
> **老人戴一个智能手环**，实时监测心率、血氧，跌倒自动报警；
> **村级专员和家属**收到预警后第一时间响应处理；
> **政府部门**在后台大屏上实时看到全区老人的健康状态和服务情况。
>
> 下面我分三个方面向各位老师汇报：项目背景、系统功能、技术实现。

**为什么这样开场？** → 30 秒让评委知道"这是做什么的"，不绕弯子。

---

## 二、PPT 配合话术（5 分钟）

如果你有 PPT，按以下 4 页讲，每页对应一个核心信息点：

### 第 1 页：痛点 + 价值（1.5 分钟）

**你讲：**
> 我国农村空巢老人比例已超过 60%。这些老人最大的问题是：**摔倒了没人知道、走丢了没人找、有需求没人帮**。
>
> 市面上小米手环、Apple Watch 定位是城市年轻人，没有针对农村场景的防摔雷达和 SOS 功能；第三方养老平台又太贵，村级财政买不起。
>
> 所以我们自研了这个系统——用最便宜的 ESP32 芯片做手环，自己搭后端服务，一套代码同时支持 Web 和 APP。

### 第 2 页：系统架构（1.5 分钟）

**你讲：**
> 系统分三层：
> - **感知层**——自研手环，带心率血氧传感器、毫米波雷达（跌倒检测）、GPS 定位
> - **平台层**——Node.js 后端、MySQL 数据库、自建 MQTT 消息中间件
> - **应用层**——面向政府/村级/服务商的 Web 管理端 + 面向老人/家属的 APP
>
> 数据流转：手环采集 → 串口 → MQTT → 设备引擎 → 数据库 → 前端展示。

### 第 3 页：功能亮点（1 分钟）

**你讲：**
> 系统有五个核心功能：
> 1. **实时体征监测**——心率、血氧、体温、步数、定位
> 2. **智能告警引擎**——心率异常、跌倒、SOS、电子围栏越界自动预警
> 3. **三级预警流转**——村级专员→乡镇→区县，超时自动升级
> 4. **服务工单闭环**——预约→审批→派单→服务→评价
> 5. **数据大屏**——全区养老数据可视化

### 第 4 页：技术难点 + 个人贡献（1 分钟）

**你讲：**
> 我主要负责后端 IoT 数据链路和设备监控模块。其中最大的技术难点是**硬件数据接入的格式兼容问题**——ESP32 输出的是纯文本调试日志，而后端引擎需要 JSON 数据。我通过在后端串口桥中增加正则解析，零侵入地打通了数据链路，既保留了硬件原有的显示屏功能，又让数据成功流入了系统。

## 三、实机演示脚本（7 分钟，最关键部分）

> ⚠️ **PPT 讲完后，立刻切换到浏览器进行实机演示。硬件演示是最大亮点，一定要展示！**

### Step 1：演示 Web 管理端（2 分钟）

| 操作 | 说话内容 |
|------|---------|
| 用 `gov_admin / admin123` 登录 | "我先用政府管理员账号登录" |
| 点击左侧 **工作台** | "这是数据总览——老年人口数、设备在线率、今日预警数、服务工单数一目了然" |
| 点击 **系统管理 > 设备监控** | "这是设备监控页面——所有手环的实时数据，心率、血氧、电池等" |
| 翻到页面底部 | "如果手环离线，这里会显示离线状态，并自动告警" |

### Step 2：演示移动端 H5（1 分钟）

| 操作 | 说话内容 |
|------|---------|
| 按 **F12** 打开开发者工具，点 **手机模式图标** | "接下来展示老人端——我切换到手机模式" |
| 刷新页面，用 `elderly_user / elderly123` 登录 | "用老人账号登录" |
| 指一下屏幕上的体征卡片 | "老人打开手机就能看到自己的心率、血氧——5 秒自动轮播，不用操作" |
| 指一下 **SOS 按钮** | "这个 SOS 按钮需要长按 3 秒才触发，防误触设计" |

### Step 3：硬件联动演示（2 分钟，最精彩的部分）

| 操作 | 说话内容 |
|------|---------|
| 拿出 ESP32 手环实物，展示给评委看 | "这是我们的自研手环——成本不到 40 元" |
| 指一下手环的圆形屏幕 | "带显示屏，实时显示心率和血氧" |
| 把手环握在手里，用力晃动一下 | "如果我模拟一个跌倒动作——" |
| 切回后端终端窗口，**指着日志** | "看！后端马上收到告警——FALL_DETECTED" |
| 切回浏览器，刷新设备监控页 | "前端也会同步弹出告警记录" |

> **效果**：从物理动作 → 后端日志 → 前端界面，评委能直观感受到整个数据回传过程。

### Step 4：预警-工单流程（1 分钟）

| 操作 | 说话内容 |
|------|---------|
| 退出登录，用 `village_staff / staff123` 登录 | "我用村级专员账号处理预警" |
| 点击 **养老服务 > 预警处理** | "这里能看到刚才产生的告警——我点确认处理" |
| 退出，用 `provider_user / provider123` 登录 | "切换到服务商账号，可以看到派单" |

### Step 5：总结（1 分钟）

| 操作 | 说话内容 |
|------|---------|
| 切回答辩状态 | "以上就是整个系统从硬件采集到平台处理再到业务流转的完整演示。" |

## 四、常见突发情况应对

### 情况 1：硬件没反应 / 数据没出来

**不要说**："等一下我再看看……"（很尴尬）

**要说**："由于演示环境限制，硬件连接不太稳定。我换成软件模拟器来展示——大家看，后端日志显示模拟数据已经正常流入系统了，逻辑是一样的。"

然后快速在终端启动模拟器，前端刷新即可。

### 情况 2：被问到没准备的问题

**不要说**："这个我不太清楚……"

**要说**："这个问题很好。目前我们的实现中 XXX 是这样做的。但您说的方向确实很有启发，如果有机会迭代，我会重点考虑这个点。"

→ 先回答已知部分，再承认不足，最后表达改进意愿。

### 情况 3：评委质疑"和 XX 项目有什么区别"

**要说的**：
> 我了解过 XX 项目，他们主要是做 XXX（一句话概括）。我们的核心差异在于两点：一是我们是**硬件+软件全栈自研**，不是纯软件系统；二是我们聚焦**农村四级联动**（老人→家属→村级→政府），而不仅仅是某一个角色的管理系统。

### 情况 4：设备掉线、网络断了、页面卡住

**要说的**（淡定）：
> 系统设计时我们内置了离线容错机制——这个界面上次缓存的数据还在。如果是在真实部署环境，MQTT 有自动重连，几百毫秒就会恢复。我刷新一下。

## 五、评委最可能追问的 6 道题（附一句话回答）

| 问题 | 一句话回答 |
|------|-----------|
| **你们的数据安全怎么保障？** | "JWT 24 小时过期 + bcrypt 加盐哈希 + 日志脱敏，三管齐下" |
| **老人不会用手机怎么办？** | "核心功能不依赖手机——SOS 和跌倒检测靠手环硬件完成，4G 模块直接上传" |
| **和市面上的手环比有什么优势？** | "成本 40 元 vs 几百元；开放式数据可对接政府平台；双传感器跌倒检测误报率更低" |
| **手环续航多久？** | "当前原型 6-8 小时，量产后优化到 3-5 天——深度睡眠 + BLE 低功耗传输" |
| **你怎么验证数据能实时传到后端？** | "每 5 秒打一行日志，数据延迟 3-5 秒，现场可以实时看到" |
| **这个项目你做了多少？团队其他人做了什么？** | "我负责后端 IoT 链路和告警引擎；另一位同学负责前端和 APP；还有一位同学负责 ESP32 硬件固件" |

## 六、答辩前 Checklist

### 电脑准备

- [ ] 打开浏览器，已登录 `gov_admin`
- [ ] 打开 **第二个标签页**（手机模式，已登录 `elderly_user`）
- [ ] 打开 **后端终端窗口**（可看到实时日志）
- [ ] ESP32 手环已连接电脑（COM7）
- [ ] 后端服务正常运行（`http://localhost:8080`）
- [ ] 前端服务正常运行（`http://localhost:3001`）
- [ ] 演示切换账号的密码都记在便利贴上

### 演示顺序备忘

```
1. 开场介绍（1分钟）→
2. PPT 四页（5分钟）→
3. 实机演示：
   a. Web 管理端 - 数据总览（1分钟）
   b. 设备监控页面（1分钟）
   c. 老人 APP（1分钟）
   d. ⭐ 硬件联动 - 晃手环、看日志（2分钟）
   e. 预警工单流转 - 角色切换（1分钟）
4. 总结 + 回答问题（5分钟+）
```

### 着装与仪态

- 穿正装或商务休闲
- PPT 翻页用翻页笔，不要频繁回头
- 演示时站在电脑一侧，**手指向屏幕**说话，不要挡屏幕
- 手环展示时**拿起来朝向评委**，不要放在桌上指
